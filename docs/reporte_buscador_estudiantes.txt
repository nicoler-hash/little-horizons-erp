3. RESPONSABILIDAD DE CADA CLASE (MVC)
-------------------------------------------------------------------------------
MODELO - Estudiante
  - DTO que reúne datos de tres tablas: estudiantes, matriculas y grados.
  - getNombreCompleto(): une primer nombre, segundo nombre, primer apellido
    y segundo apellido, descartando los nulos o vacíos. Así no quedan
    espacios dobles cuando un segundo nombre o apellido es NULL.
  - getDocumento(): devuelve tipo y número de documento (ej. "TI 1023456789").

VISTA - BuscadorEstudiantesMain
  - Contiene el main(); se ejecuta sin login ni menú del ERP.
  - Muestra el menú principal y el submenú de grados.
  - Valida la entrada: texto, 0 (cancelar), número fuera de 1-12.
  - Muestra los resultados o el mensaje de "no se encontraron".
  - No contiene SQL.

CONTROLADOR - BuscadorEstudiantesController
  - consultarEstudiantesActivos(): ejecuta la consulta JDBC.
  - filtrarPorGrado(): aplica el filtro con Stream API.
  - buscarPorGrado(): consulta y luego filtra.
  - No imprime en pantalla.

4. CONSULTA SQL
-------------------------------------------------------------------------------
SELECT e.id_estudiante, e.tipo_documento, e.numero_documento,
       e.primer_nombre, e.segundo_nombre, e.primer_apellido, e.segundo_apellido,
       g.id_grado, g.nombre_grado
FROM estudiantes e
JOIN matriculas m ON m.id_estudiante = e.id_estudiante
JOIN grados g ON g.id_grado = m.id_grado
WHERE m.anio_academico = ? AND m.estado_matricula = ?
ORDER BY g.nivel_numerico, e.id_estudiante

Explicación:
  - Primer JOIN: relaciona cada estudiante con su matrícula.
  - Segundo JOIN: relaciona la matrícula con su grado.
  - WHERE: deja solo matrículas del año 2025 con estado 'Activa'.
  - Los signos ? son parámetros de un PreparedStatement (evita inyección SQL).
  - Los nombres de columnas se tomaron del esquema real de docs/database.sql.

Observación: el enunciado menciona "año_academico", pero la columna real de
la base de datos es "anio_academico" (sin ñ). El código usa el nombre real.


-------------------------------------------------------------------------------
5. FILTRO CON STREAM API
-------------------------------------------------------------------------------
return estudiantes.stream()
        .filter(estudiante -> estudiante.getNombreGrado() != null
                && estudiante.getNombreGrado().equalsIgnoreCase(nombreGrado))
        .collect(Collectors.toList());

  - stream()                      convierte la lista en un flujo de datos.
  - filter(lambda)                conserva solo los del grado elegido.
  - collect(Collectors.toList())  reúne el resultado en una nueva lista.

6. MANEJO DE CASOS ESPECIALES
-------------------------------------------------------------------------------
  - Sin matrícula activa en 2025 ........ el WHERE los excluye.
  - Grado sin estudiantes ............... mensaje "No se encontraron...".
  - Segundo nombre/apellido NULL ........ getNombreCompleto() evita espacios dobles.
  - Datos incompletos ................... se descartan partes nulas o vacías.
  - Error de conexión MySQL ............. mensaje comprensible y regreso al menú.
  - Recursos JDBC ....................... try-with-resources cierra Connection,
                                          PreparedStatement y ResultSet.
  - Entradas inválidas .................. el programa no termina; permite reintentar.

10. PREGUNTAS PROBABLES DEL INSTRUCTOR
-------------------------------------------------------------------------------
P: ¿Dónde está el Stream API?
R: En filtrarPorGrado() del controlador: stream(), filter() con lambda y
   collect(Collectors.toList()).

P: ¿Por qué no filtras el grado en el SQL?
R: Porque el enunciado exige hacerlo con Stream API. El SQL solo trae los
   estudiantes con matrícula activa de 2025.

P: ¿Qué es un DTO?
R: Un objeto que transporta datos combinados de varias tablas. Estudiante
   junta datos de estudiantes, matriculas y grados.

P: ¿Cómo evitas espacios dobles en el nombre?
R: Con un Stream que descarta las partes nulas o vacías antes de unirlas
   con Collectors.joining(" ").

P: ¿Qué es PreparedStatement y por qué se usa?
R: Una consulta con parámetros (?). Evita la inyección SQL.

P: ¿Cómo se cierran los recursos JDBC?
R: Con try-with-resources: Connection, PreparedStatement y ResultSet se
   cierran solos aunque ocurra una excepción.

P: ¿Dónde se ve la separación MVC?
R: El modelo no imprime, la vista no tiene SQL y el controlador no usa
   System.out.

P: ¿Por qué reutilizas DatabaseConnection?
R: Porque el enunciado pide reutilizar la conexión existente en lugar de
   duplicar el código.
